# v2026.925.0-zhtw.7

**類型**：安全與穩定度（Phase 0 止血）　**基於**：v2026.925.0-zhtw.6　**建版目標 commit**：`161f06d`

## 摘要

針對「代理人隨時切換模型／轉接器」做的第一批保護。含一項安全修正、三項切換保護、兩個給小主機用的環境變數，以及 Pi／OpenCode／Gemini 的限流分類。設計背景見 `doc/plans/2026-09-26-agent-cowork-architecture-review.md`。

## 變更

### 安全
- 代理人用自己的 API key 修改自己的 `name`／`role`／`title`／`capabilities` 時，一律要先取得看板同意（request confirmation），不論請求裡有沒有夾帶其他欄位。修正前只要多帶一個欄位就能把自己升成 CEO。

### 切換保護
- 有 queued／running／scheduled_retry 的 run 時切換轉接器會回 409 `agent_runs_active`；介面會問你要不要「取消這些 run 並切換」；API 呼叫加 `?cancelActiveRuns=true` 才會取消後切換。
- 任務層的模型覆寫（Model lane）在建立與更新任務時就檢查是否與指派代理人的 AI 連線相容，不相容回 422 `ai_connection_incompatible`，不必等到任務執行才失敗。
- run 結束時若代理人的轉接器已被切換，不再把舊轉接器的 session 與 adapterType 寫回 runtime state，也不會重建舊 session。

### 穩定度
- 新增環境變數 `PAPERCLIP_MAX_CONCURRENT_RUNS`：整台主機同時執行的 run 上限（KVM 2 建議 `2`），超過的 run 排隊等下一個排程 tick。
- 新增環境變數 `PAPERCLIP_LOCAL_ADAPTER_TIMEOUT_SEC`：本機／SSH 執行且代理人未設 `timeoutSec` 時的預設逾時（建議 `5400`）。
- Pi、OpenCode、Gemini 轉接器會把供應商的限流（429、overloaded）與額度用盡（quota、insufficient credits）分類為 `transient_upstream`／`provider_quota` 並帶上 `retryNotBefore`，伺服器據此排程重試或額度監視，不再把代理人打進 error。

- 代理人用自己的 key `PATCH /api/agents/<自己>` 帶 `{ "role": "ceo", "icon": "bot" }` → 403。
