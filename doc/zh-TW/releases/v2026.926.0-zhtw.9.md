# v2026.926.0-zhtw.9

**類型**：修正版（安全）　**基於**：v2026.925.0-zhtw.8　**建版目標**：`main`

## 摘要

修掉「在代理人設定頁按儲存，會把密鑰存成 `***REDACTED***`」的問題。舊版讀取代理人設定時會遮住看起來像密碼的欄位，但儲存和「測試環境」只把 env 區塊換回真值，其他欄位（headers 的 token、`authToken`、裝置私鑰 `devicePrivateKeyPem`，連名稱含 auth 的開關 `disableDeviceAuth`）都會把遮罩字串原樣寫進資料庫。OpenClaw 閘道器代理人因此出現 `DECODER routines::unsupported` 與 `token_mismatch`。

## 變更

### 修正
- 儲存（`PATCH /api/agents/:id`）與測試環境：畫面送回的遮罩字串，會換回資料庫裡同一個位置的真值。只有「原本就會被遮住的欄位」才會回填，值不會跑到別的欄位。找不到舊值的遮罩字串會被丟掉；其他無法安全回填的情況回 422，並列出需要重新填寫的欄位。
- 以下情況不回填，一律要求重新填寫：
  - **陣列被改過**：陣列（例如命令參數、MCP 伺服器清單）是照位置對應的，整個陣列原樣送回才回填；重排、增刪或改了其中一項都要重填，避免 A 的密鑰被放到 B。
  - **資料庫裡的舊值本身就是遮罩字串**：以前存壞的欄位，存檔時會被標出來，不會再被原樣寫回。
  - **env 的遮罩字串被改過**。
- 布林值不再被遮罩（開關不可能是密鑰；遮了反而會被存成字串）。舊分頁送回布林欄位的遮罩字串時，會拿回資料庫裡的開關值。數字仍會遮罩，儲存時會還原。
- 切換轉接器類型時，env 以外的遮罩值一律拒收（422），不會把舊密鑰帶到新的轉接器。
- 切換轉接器並要求「取消執行中的 run」時，會先檢查遮罩值再取消 run。之前在 zhtw.8 上，被拒絕的切換仍會先把 run 取消掉。
- 設定版本還原（revision rollback）：原本只擋「完全等於」遮罩字串的值，現在只要含遮罩字串就擋（例如 `run --api-key ***REDACTED***`）。
- 建立與聘用代理人（包括「複製代理人」）：複製來的完整遮罩字串會被拿掉，新代理人要自己補填密鑰；被改過的遮罩字串回 422。之前會把遮罩字串原樣存進新代理人。

### 已知限制（不在本版處理）
- 改了連線網址或命令、但沒有重填密鑰時，存著的密鑰會沿用並送到新的目的地（env 在上游本來就是這樣）。要改成「換目的地就要求重填」，需要逐一設計各轉接器的規則，並讓設定頁能填每個隱藏欄位（例如 OpenClaw 的裝置私鑰目前沒有欄位），排入下一版。目前只有具備代理人設定權限的管理員能做這種修改，代理人不能改自己的設定。
- 取消 run 之後，切換仍可能因其他檢查（AI 連線相容性、環境選擇等）被拒絕，此時 run 已經取消。這是 zhtw.8 既有的順序問題，本版只把遮罩值這一種檢查挪到取消之前。
- 沒有更新權限、但有公司權限的使用者送出含遮罩值的存檔，可能先收到 422 而不是 403。

### 測試
- 新增 `server/src/__tests__/redaction-restore.test.ts`，並在 `agent-permissions-routes`、`agent-adapter-validation-routes` 加入回歸測試。拿掉修正時這些測試會失敗。

## 升級注意
- 沒有資料庫遷移。照 `doc/zh-TW/VPS-DEPLOY.md` 第 8 節先備份，再照第 7 節升級。
- 已經被存成 `***REDACTED***` 的欄位，這版不會自動修復。存檔時會回 422 並列出這些欄位，重新填寫真值（或從備份還原該代理人的設定）後才能儲存。OpenClaw 的裝置私鑰在設定頁沒有欄位，如果它是壞的，要直接修資料庫（升級前可先掃描哪些代理人有殘留）。
- 升級前，已經壞掉的代理人仍不要按儲存。升級後，儲存不會再把遮罩字串寫進資料庫。

## 驗證
1. 打開一個 OpenClaw 閘道器代理人的設定頁，不改任何東西直接按儲存。
2. 資料庫裡該代理人的 `adapter_config` 不含 `***REDACTED***`，`devicePrivateKeyPem` 仍可被解析，`disableDeviceAuth` 仍是布林值。
3. 派一個新任務給該代理人，能正常跑完。
