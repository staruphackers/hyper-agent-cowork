# v2026.1003.0-zhtw.10（草稿，版本號以實際發版日為準）

**類型**：修正版（OpenClaw 串接穩定版＋安全）　**基於**：v2026.926.0-zhtw.9　**建版目標**：`main`

## 摘要

把 2026-09 第一次接 OpenClaw（Hostinger VPS）時靠人手修的問題，改成由產品自己擋住或講清楚；並修掉兩個安全問題：「需要董事會核准的聘用」會把遮罩字串寫進新代理人，以及加入時提供的金鑰路徑可以夾帶指令文字、每次喚醒都送給遠端代理人。

## 變更

### 安全
- **核准聘用不再寫入遮罩字串**：需要核准的聘用，申請時存的設定快照是遮罩過的；舊版核准時直接拿快照蓋掉代理人的真實設定，OpenClaw 的私鑰、token 會變成 `***REDACTED***`（其他轉接器則是核准失敗）。現在核准時會把遮罩欄位換回代理人原本的值；換不回去就回 422（`hire_approval_redacted_values`），核准維持待處理。上游同型問題：#14002、#14048。
- **金鑰路徑只收純檔案路徑**：`claimedApiKeyPath` 只能是 `/` 或 `~/` 開頭、`.json` 結尾，只含英文字母、數字與 `. _ - /`，不可有 `..`。不符合的值在加入時會被忽略、執行時改用預設路徑；喚醒訊息會用反引號包住路徑，並註明它是檔案路徑、不是指令。
- **換 Gateway URL 要重填密碼**（補上 zhtw.9 的已知限制）：OpenClaw 代理人改接到另一台 gateway（主機或路徑不同，或從 `wss://` 降級成 `ws://`）時，gateway token、密碼、headers 都要在同一次存檔或測試中重新填入，否則回 422（`openclaw_gateway_reenter_credentials`）。裝置私鑰不需重填：它只在本機簽名、不會送出（有測試確認）。
- **重送邀請不能改走向**：已核准的 OpenClaw 用同一張邀請重送時，仍可更新 gateway token 與平台網址（上游原本的用途），但改 gateway 網址、金鑰路徑或關掉裝置驗證會被擋下（422 `openclaw_gateway_replay_locked_fields`）。已核准的裝置金鑰一律保留；舊版每次重送都會換掉它，導致要重新核准裝置。

### 修正
- **加入指示更安全**：明寫不得修改 gateway 設定、不得自開臨時隧道、需要重啟就停下來請管理員；範例直接帶入平台公開網址；API 金鑰存放位置與 `echo $HOME` 說明。
- **重複代理人**：核准第二個接同一台 OpenClaw 的加入申請時擋下（409），所有核准入口都會顯示是哪個代理人、要怎麼處理（之前有兩個入口不顯示錯誤，按了沒反應）；`ws://` 與 `wss://` 視為同一台。
- **錯誤講清楚**：缺 scope 回 `openclaw_gateway_missing_scope`、私鑰壞掉回 `openclaw_gateway_device_key_invalid`，各附一句修法；設定頁勾選「停用裝置認證」時顯示警告。
- **測試連線像真的派工**：帶裝置簽章連線、顯示 OpenClaw 實際給的權限、被拒時顯示原因、需要核准時顯示可直接複製的 `openclaw devices approve <requestId>`。
- **預設逾時 600 秒**（原 120 秒）：OpenClaw 做超過 2 分鐘的任務不再被記成失敗。只影響新代理人；既有代理人請到設定頁把「超時（秒）」改成 600、「等待超時（毫秒）」改成 600000。
- **繁中用語**：修正 20 條直譯語序（例如「封存來自收件匣」→「從收件匣封存」、「簽名中到繼續」→「登入以繼續」），並加測試防止再出現。

### 新增
- 唯讀健檢腳本 `scripts/openclaw-doctor.mjs`：列出每個 OpenClaw 代理人的 PASS／WARN／FAIL，不印密碼、金鑰、網址帳密或參數、自訂路徑。
- 繁中串接指南 `doc/zh-TW/OPENCLAW-INTEGRATION.md`。

### 已知限制
- 「換 Gateway URL 要重填」只套用在 OpenClaw；其他轉接器維持 zhtw.9 的行為。
- 設定頁仍沒有裝置私鑰欄位（換金鑰要走資料庫或重新加入）。
- 金鑰路徑規則仍允許用 `_`、`-` 連成的英文字串；現在只有加入的那一方能設定，且重送邀請不能再改它。

### 測試
- 每項修正都有測試，並做過反向對照（拿掉修正時新測試會失敗）。新增測試檔：`agents-pending-approval-config`（擴充）、`approvals-service`（擴充）、`openclaw-credential-guard`、`join-request-approve-duplicate-gateway`、`invite-replay-approved-openclaw`、`ui/src/lib/join-request-approve-error`；並擴充 `agent-permissions-routes`、`agent-adapter-validation-routes`、`openclaw-gateway-adapter`、`invite-accept-gateway-defaults`、`heartbeat-stop-metadata`、`build-config`、`openclaw-doctor`、`AttentionQueueRow`、`locale-validation`。
- 已知既有失敗（與本版無關）：`agent-instructions-routes` 切換轉接器 ×2、`chat-channels.integration` ×2、`InstanceExperimentalSettings`「alphabetizes cards」×1。

## 升級注意
- 沒有資料庫遷移。照 `doc/zh-TW/VPS-DEPLOY.md` 先備份再升級。
- 升級後到既有 OpenClaw 代理人的設定頁，把逾時改成 600 秒。
- 升級後在平台容器跑一次健檢：`docker exec -i <平台容器名稱> node /app/scripts/openclaw-doctor.mjs`。

## 驗證
1. 健檢腳本：OpenClaw 代理人沒有 FAIL。
2. 設定頁不改內容按儲存，再跑一次健檢仍沒有 FAIL。
3. 測試連線顯示 probe succeeded，權限含 `operator.write`。
4. 派一個新任務（超過 2 分鐘的也可以）→ 收到回覆、代理人自己把任務標成完成。
