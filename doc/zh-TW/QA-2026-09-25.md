### 2.2 擷取機制的改進（`ui/i18n-tools/babel-plugin-i18n-wrap.mjs`）

1. 物件屬性白名單（`label`／`title`…）的值若是單一個首字大寫英文單字（`label: "Unread"`），現在也會包裝。
2. JSX 位置的三元／`||`／`??` 運算式（`{prev ? "Reconnect" : "Connect"}`），其單字分支會收進字串清單，讓字典補得到。
3. 以 id 為 key 的標籤對照表（`request_confirmation: "Confirmations"`）的值也會收進清單。

三條規則各有測試（`ui/src/i18n/wrap-plugin.test.ts`，共 32 個測試），原始 TSX 依然一字不改。

### 2.4 已知限制（需要動上游 TSX 才能解，本 fork 刻意不做）

- **帶插值的模板字串**：`` `${name} is ready to work!` ``（新手引導）、`` `Default resolver audience for ${kind}` ``（設定頁 aria-label）、`` `Export ${n} files` ``、`` `${weeks} weeks`` `` 仍顯示英文。
- **活動紀錄的動詞**：`company.created → "created organization"` 這類對照表在 `activity-format.ts` 以句子組裝，儀表板「最近活動」會看到「董事會 created organization」。
- **相對時間**：`14m ago`、`just now` 由格式化函式產生。
- **agent 產生的內容**（任務說明、留言、報告）不在介面翻譯範圍。

### 3.2 翻譯會不會改變程式邏輯？

風險模型：建置期包裝只發生在 JSX 文字、白名單屬性、白名單物件值；程式裡的比較式（`status === "admin"`）不會被包裝。掃描了 1,080 個原始檔，找出 74 處「被翻譯的字串同時出現在比較式」的案例，逐一確認比較的是 API 原始值（`role`、`status`、`kind`），不是顯示文字，**沒有功能風險**。
