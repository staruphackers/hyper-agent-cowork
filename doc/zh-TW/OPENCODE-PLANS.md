# OpenCode Zen 與 Go：方案差異、介面設定與自動偵測

適用版本：`v2026.925.0-zhtw.3` 起。上游 Paperclip 的 OpenCode 轉接器只接 OpenRouter 連線；本發行版加入了「供應商 API 金鑰」登入方式與方案偵測。

## 1. 兩個方案的差異

| 項目 | OpenCode Zen | OpenCode Go |
| --- | --- | --- |
| 計費 | 儲值、按 token 計費 | 月費 10 美元，每個模型有月額度（15～60 美元），5 小時 20%、每週 50% |
| 模型 id 前綴 | `opencode/` | `opencode-go/` |
| 模型範圍 | 100 多個，含 Claude、GPT、Gemini、Grok，另有 9 個免費模型 | 41 個開放權重模型：DeepSeek、GLM、Kimi、Qwen、MiniMax、MiMo、Grok 等 |
| 金鑰 | 同一把 `OPENCODE_API_KEY`，在 OpenCode 的 console 產生 | 同一把 |
| 額度用完 | 儲值歸零就停 | 可在 console 開「Use balance」改扣 Zen 儲值 |

免費模型的 id 以 `-free` 結尾，`big-pickle` 是唯一沒有後綴的免費模型。沒有金鑰時 OpenCode 只列免費模型，這就是新增代理人時只看到 7 個模型的原因。

## 2. 在介面上設定（不用進容器）

1. 新增代理人 → 轉接器選 **OpenCode** → 填名稱進入設定畫面。
2. **登入方式** 選「供應商 API 金鑰」。
3. **API 金鑰供應商** 選 OpenCode Go 或 OpenCode Zen（兩者共用同一把金鑰，選哪個只影響預設的模型前綴），把金鑰貼進 `OPENCODE_API_KEY`。
4. 按 **檢查方案**。平台會拿這把金鑰分別詢問 Zen 與 Go 的模型端點，顯示：
   - `OpenCode Go · 月費方案`：已開通／未開通／無法確認，以及付費與免費模型數。
   - `OpenCode Zen · 儲值計費`：同上；若只列出免費模型，會顯示「只有免費模型，儲值或訂閱後才會解鎖其他模型」。
5. 模型下拉會依方案分組，免費模型有「免費」標記；這把金鑰不能用的模型預設隱藏，勾選「顯示這把金鑰不能用的模型」可以看全部。選到不能用的模型會出現紅字警告，但不會阻擋（可能你剛訂閱）。
6. 按 **執行測試** 做最後驗證，再按 **完成設定**，然後到代理人設定填每月預算上限。

既有的 OpenCode 代理人：到代理人設定頁的模型區塊按「檢查方案」，平台會用已儲存的密鑰重新偵測。

## 3. 偵測怎麼運作、有什麼限制

- 平台呼叫 `https://opencode.ai/zen/v1/models` 與 `https://opencode.ai/zen/go/v1/models`，帶你的金鑰，逾時 8 秒。端點回 200 且有模型就是「已開通」，回 401／402／403 是「未開通」，其他情況是「無法確認」。
- 金鑰只在請求過程中使用，不會被偵測功能儲存或寫進 log。建立代理人時金鑰照舊存成組織密鑰。
- 每個公司每分鐘最多 12 次偵測。
- Go 的端點在 models.dev 註明為未公開文件的介面，格式若變動，偵測會顯示「無法確認」並退回容器內的模型清單，不影響建立代理人。
- 偵測只是查詢，不產生模型費用。

## 4. 選模型與費用控管

- 策略型、需要長推理的代理人：用方案裡最強的模型。
- 例行整理、格式化、摘要：用便宜或免費模型。
- Go 方案的額度是「每個模型各自計算」，同一個代理人切換模型不會共用額度。
- 不管哪個方案，代理人的每月預算上限都要填，這是平台端的最後閘門。
